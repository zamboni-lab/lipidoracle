Retention-time consistency

WORKFLOW.rt_check selects one retention-time plausibility filter, applied after MS1 and MS2 matching. It removes annotations that imply a structure whose expected retention time does not match where the peak actually eluted.

WORKFLOW:
  rt_check: liri   # False | 'legacy' | 'liri' (default) | 'hydra'

Exactly one engine ever runs. The value is case-insensitive, and True is accepted as a synonym for 'legacy'. An unrecognised string fails configuration validation loudly rather than silently disabling the check.

Why it works

Lipids are modular: a headgroup plus one or more acyl, alkyl, or sphingoid chains. In reversed-phase LC, retention is dominated by hydrophobic surface area, which follows that same modular structure fairly predictably. More carbons elute later, more double bonds or oxygens elute earlier, and a given headgroup shifts its whole homologous series by roughly a constant amount.

That regularity is what makes the check possible. A wrong MS1 or MS2 annotation is often also a retention-time outlier. All three engines exploit this the same way at a high level: fit an expected-RT model from confident annotations in this run, optionally sharpened by an external anchor file, then flag candidates whose observed RT deviates from that expectation by more than a calibrated number of standard deviations. They differ substantially in how that model is built and how conservative the resulting judgement is.

Every engine works without any external reference file, purely from this run's own confident annotations.

Reference data

To reduce spurious identifications, we recommend building a retention-time library for each gradient, from standards or manually validated IDs. Point at it with:

PARAM:
  rt_ref: '/output/rt_ref_2min.csv'

The CSV must have these columns:

Column Meaning
hg Lipid class
c Total number of carbons
db Total number of double bonds
mod Modifications, separated by spaces
rt Retention time in seconds 
hg,c,db,mod,rt
SM,30,0,O2,53.46
SM,40,0,O2,90.3
SM,41,0,O2,93
SM,42,0,O2,96.54
SM,32,0,O2,61.5

External anchors are never trusted on their own time axis. They are first aligned onto this run's RT axis through a robust monotone warp, which is outlier-trimmed and leave-one-out validated. If too few pairs match, or the leave-one-out error is too high, the alignment is refused outright and the engine falls back to running anchor-free. A reference file from a different gradient will therefore not silently corrupt the fit.

The engines

liri, the default

LiRI does not regress retention time directly. It builds a retention index, a structural score in carbon-equivalent units:

h = C - a_db * DB - a_o * O

then fits a monotone map from h to RT independently for each (class, ether) group, using only that group's own anchors. The a_db and a_o coefficients are fitted once globally across all anchors, since borrowing statistical power for that single ratio is safe. The retention curve itself is never shared between classes.

Each candidate is graded into a tier that determines how forcefully it can be rejected:

Tier Meaning Can hard-reject
A Exact structural match to an anchor Yes
B Within its group's own anchored range Yes
C Extrapolated beyond its group's anchored range Soft only
D No local map exists for this (class, ether) Never checked

A hard rejection bypasses score protection. A soft rejection is forgiven for high-confidence, score-protected idlevel 2 annotations.

The deliberate limitation. A class with too few anchors of its own gets no prediction at all, rather than a rough guess. This was a design decision, not an oversight. Earlier versions shared a curve across classes, and two later attempts added a cross-class fallback for exactly the classes that lack their own anchors. All were tested on real data and reverted, because each reintroduced the same failure: a class with a genuinely different retention slope gets pulled into a curve shaped by steeper, unrelated classes and mispredicted by tens of seconds. Triacylglycerols are the recurring example, since their per-carbon retention gain flattens out where glycerophospholipids are still climbing steeply.

The practical consequence is that LiRI cannot flag an implausible idlevel 1 hit in a class it has never confirmed by MS2 in this run or seen in rt_ref. FA and CE are the usual cases. LiRI is safe, in that it will not remove something wrongly for lack of evidence, but it is not complete, in that classes without evidence pass through unfiltered no matter how implausible their RT is.

hydra

HYDRA takes the opposite side of the same tradeoff. It keeps one shared monotone calibration curve, but shares information across classes at the feature level rather than the curve level.

Each candidate's structure is encoded as a feature vector: headgroup fragment composition (atom counts, charge, rings, built from the same fragments used to generate full structures, so PC, LPC, and SM all receive an identical phosphocholine descriptor), a lipid-family indicator, and chain-inventory terms held at fixed chemistry priors. A class with anchors gets its own learned offset on the shared curve. A class without anchors has its offset predicted by regression from other classes' learned offsets onto their shared descriptors, which is an approximate but chemistry-informed guess rather than no prediction at all.

HYDRA also computes a pairwise relative z-score from a constraint graph over nearby anchors, checking whether a candidate's RT is ordered correctly relative to its neighbours and not just against the absolute curve.

What this buys. HYDRA can flag an implausible hit in a class with zero anchors of its own, purely from shared chemistry. A real FA 22:1;O2 annotation co-eluting at 114.5 s, where fatty acids that size normally elute around 25 s, was correctly caught and removed through this path. LiRI structurally cannot touch that case.

What it costs. rt_hydra_z_soft_ms1 (default 0.75) applies a much stricter threshold specifically to idlevel 1 candidates, roughly four times tighter in z-units than the value used elsewhere. That is tight enough to reject a substantial fraction of correct annotations by chance alone. In practice HYDRA removes about twice what LiRI removes, and where the two disagree, HYDRA's extra removals are disproportionately correct annotations being discarded. Where LiRI and HYDRA agree that a candidate is bad, they are right about 93% of the time. Agreement between the two is a strong signal; HYDRA disagreeing with LiRI is not.

If you use HYDRA, consider first raising rt_hydra_z_soft_ms1 toward rt_hydra_z_soft (3.0), or setting it to 0 to disable the idlevel 1 special case entirely. That single default is the largest known lever on HYDRA's precision.

legacy

Two independent linear regressions, always run together:

  • Generic: fits RT against elemental formula features (C, H, N, O, P, S, and degree of unsaturation) by robust ridge regression across all classes pooled, with one global tolerance (rt_generic_cutoff, default 60 s). Needs at least 24 training rows or it does nothing.
  • Class-specific: fits a separate rt ~ C + DB + O regression per class, plus two hardcoded structural rules for triacylglycerols eluting too early and lyso species eluting too late.

This is a linear-in-RT model, so it assumes a roughly constant seconds-per-carbon slope. That assumption breaks down in the late gradient, and several hand-tuned exceptions in the code compensate for it rather than fixing the model shape.

Measured removal precision is close to a coin flip. It is superseded by LiRI on every metric measured, and is kept for rollback and direct comparison rather than as a working default.

At a glance

legacy liri hydra
Model shape Linear in RT Monotone index to RT, per class Monotone index to RT, shared curve plus per-class offset
Cross-class sharing None, or full pooling None, deliberately Yes, through shared headgroup and family features
Classes with no anchors Crude or none Never checked Covered by offset regression
Failure mode on thin data Linear-model noise Silence: never wrong, never complete Possible over-removal, mostly at idlevel 1
Removal precision ≈ 0.46 ≈ 0.77 ≈ 0.74
Missed anchors by more than 10 s 27 3 3

The precision and false-negative figures come from one audit on one dataset. Treat them as illustrating the shape of the difference, not as universal constants: they will shift with dataset and gradient.

Which to use

Default to liri. It matches HYDRA's removal precision with a smaller, better-understood footprint and a hard safety property: a class it has no evidence for is never touched. The tradeoff you accept is that false annotations survive in classes without rich MS2 spectra.

Use hydra when idlevel 1 confidence matters most, for example a study with many classes that rarely get MS2 confirmation, where LiRI's silence on those classes is a bigger practical problem than HYDRA's occasional over-removal elsewhere. Loosen rt_hydra_z_soft_ms1 first.

Use legacy only for rollback or comparison.

Use False when validating a new sample type or gradient where you do not yet trust any RT-based judgement. Better to see everything MS1 and MS2 produced and filter by hand than to lose candidates silently to a model calibrated on the assumption that this run's chromatography is well behaved.

Whichever engine you pick, validate any change to its thresholds against replicate reproducibility or an rt_ref-graded audit, not just against a single run's annotation counts.
