LipidOracle Parameters Guide

All LipidOracle runs are configured via a lipidoracle.yaml file. If the file is missing, LipidOracle will generate a default configuration and exit so you can review and customise it before running.

File Structure

The YAML file has two main sections:

VERSION: x.y.z                  # Tracks configuration version

WORKFLOW:                       # Workflow switches and choices
  ...

PARAM:                          # Numeric and threshold parameters
  ...

Workflow Section

The WORKFLOW section controls which annotation engines run and how they operate.

Library & Engine Switches

Parameter Type Default Description
lipidoracle bool True Enable the internal LipidOracle MS1/MS2 annotation engine
lipidex bool False Enable LipiDex library matching (experimental, fewer features)
lipidblast bool False Enable LipidBlast library matching (experimental, fewer features)
library_extra list [] Additional CSV-format lipid libraries (e.g., ['/path/to/custom.csv'])

Data Filtering

Parameter Type Default Description
mz_target string '' Optional m/z value list file to restrict analysis to specific features (useful for targeted runs)

Advanced Analysis

Parameter Type Choices Description
acyl_analysis bool or string False, 'ead1', 'ead2', 'uvpd' Localise C=C and oxygen positions along the acyl chains; produces idlevel 3 and 4 matches. ead1 skips oxidised species; ead2 is required for anything carrying ;O. True/'v1'/'v2' are accepted aliases. See Acyl-chain analysis.
rt_check string False, 'legacy', 'liri', 'hydra' Retention-time validation engine (see RT Models for details)

PARAM Section

The PARAM section sets numeric thresholds and limits. Key parameters are listed below; the default file includes others.

Identification & Scoring

Parameter Type Default Description
rarity_max int 3 Maximum rarity index kept (lower = stricter, more conservative IDs; higher = includes rare chain compositions). Set to 0 to keep all.
rarity_penalty float 0.15 Score penalty applied to rare lipids instead of excluding them. See Lipid library.

MS1 Matching

Parameter Type Default Description
ms1_tolerance float 0.01 Precursor m/z tolerance in Da (tolerance used for MS1 library matching)
ms1_maxO int 0 Maximum extra oxygen atoms added during MS1 library generation (for oxidised variants)

MS2 Matching & Spectral Processing

Parameter Type Default Description
ms2_noise_abs int 10 Absolute MS2 peak intensity floor (peaks below this are removed)
ms2_maxO int 0 Maximum extra oxygen atoms added during MS2 isomer generation

Acyl-chain analysis (idlevel 3 and 4)

When acyl_analysis is enabled, these parameters control the exhaustive C=C and oxidation position search. Since v1.0.173 every one of them is prefixed l3_; the former ead_* and include_ms1_monochain spellings are still accepted as aliases, so existing configs load unchanged.

Parameter Type Default Description
l3_include_ms1_monochain bool True Also localise on idlevel 1 single-acyl species such as LPC/LPE
l3_max_unsaturated int 6 Caps unsaturation accepted for exhaustive search (higher = more candidates, slower runtime)
l3_max_oxygen int 2 Caps total oxygen positions across all chains. Used by ead2/uvpd; ead1 has no oxygen support and ignores it.
l3_max_candidates int 10000 Candidates scored before stride-sampling. Raise to 30000 for oxidised work — a single 20:4;O token enumerates ~22,300 candidates, and below that the true structure can be sampled out silently. See Acyl-chain analysis.
l3_max_output int 20 Candidates written to diag/annotation_idlevel3.csv per feature
l3_min_score float 0.2 Absolute score_L3 floor, applied after normalisation
l3_min_margin float 0.05 Minimum relative gap between the two best candidates before idlevel 4 names a position (ead1). Fitted against known positions.
l3_min_matched int 3 Minimum peaks the winning candidate must have matched for that gap to count (ead1)
l3_intensity_scaling string 'none' Compressive transform on matched intensity (ead2 only): none, sqrt, log10, ln, log2. ead1 always applies sqrt as part of its scoring model.
db_n_notation bool False Legacy switch: render double-bond positions in the idlevel-4 confidence tail as n-x. Canonical Shorthand2020 names always use Δ.
l3_null_decoys bool False Diagnostic only: also score chemically impossible (allene) placements as a null, adding a column to diag/l3_resolvability.csv. Never emitted as an annotation.

Candidate selection (new in v1.0.173)

Which positional isomers get reported, and how confidently idlevel 4 is named. Orthogonal to acyl_analysis: either method works with any engine.

Parameter Type Default Description
l3_selection string 'posterior' posterior converts scores to a probability distribution over candidates and reports the smallest set holding the credible level. legacy (accepted as cutoff) is the original relative-score threshold. legacy names more features but is right less often.
l3_post_credible_level float 0.95 Posterior mass the reported credible set must reach
l3_post_min_mass float 0.5 Posterior mass one placement needs before its positions are written into the idlevel-4 name. Below it the chain is reported at species level and the confidence tail still lists what is known.
l3_post_temperature float 0.01 Softmax temperature turning score gaps into probabilities. Fitted against known positions, not chosen — larger flattens the posterior towards chance, smaller manufactures confidence.
l3_legacy_cutoff float 0.99 Relative score cutoff vs the top candidate. Used only when l3_selection: legacy, and weakly discriminating: against an impossible-position null, absurd structures cleared this setting for ~11% of features.

Quick-Start Defaults

For most users, the default configuration works well:

VERSION: x.y.z

WORKFLOW:
  mz_target: ''
  lipidoracle: True
  lipidex: False
  lipidblast: False
  library_extra: []
  acyl_analysis: False
  rt_check: liri

PARAM:
  rarity_max: 3
  rarity_penalty: 0.15
  ms1_tolerance: 0.01
  ms2_tolerance: 0.02
  ms2_noise_abs: 10
  ms1_maxO: 0
  ms2_maxO: 0
  l3_max_unsaturated: 6
  l3_max_oxygen: 2
  l3_max_candidates: 10000
  l3_min_score: 0.2
  l3_selection: 'posterior'
  l3_post_credible_level: 0.95
  l3_post_min_mass: 0.5
  # ... (other parameters with defaults)

When to customise

  • Looser matching (more candidates): lower rarity_max, increase ms1_tolerance
  • Stricter matching (fewer false positives): raise rarity_max, decrease ms1_tolerance
  • Faster runs (skip acyl analysis): keep acyl_analysis: False or lower l3_max_candidates
  • Oxidised lipids: raise ms1_maxO and ms2_maxO (default 0 means no oxidation variants), pick acyl_analysis: ead2, and raise l3_max_candidates to 30000
  • More positional calls, accepting more wrong ones: set l3_selection: legacy. This also reproduces pre-1.0.173 behaviour.
  • Fewer but better positional calls: keep the default posterior and raise l3_post_min_mass
  • Targeted RT validation: choose rt_check: legacy for the original two-regression model, or rt_check: False to skip RT filtering entirely
