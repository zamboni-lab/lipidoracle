Lipid annotation from MS data

Complete annotation engine for CID, EAD, and UVPD spectra, from shortname to C=C and oxidation localization in acyl chains. Rust-based. Runs as a Docker container.

© Zamboni lab, ETH Zurich.

Install Read the paper

Every run writes a self-contained dashboard.html next to the CSVs. No server, no upload.

Two commands to a first run

LipidOracle ships as a Docker image. All input MS1 and MS2 data are provided in a single .mgf file. All settings are defined in a lipidoracle.yaml file, which is written to the output folder on the first run if it doesn't already exist.

Pull the image from Docker Hub.

docker pull zambonilab/lipidoracle

Create a local input folder. Paste the .mgf file with MS data into it. If you have a preconfigured lipidoracle.yaml, paste it in too.

Mount your folders and run. It's matter of seconds to get results!

docker run --rm \
  -v <INPUT-FOLDER>:/input \
  -v <OUTPUT-FOLDER>:/output \
  zambonilab/lipidoracle

if no lipidoracle.yaml is found in either folder, LipidOracle writes a default one to the output folder and stops so you can check it. Review the parameters, then run again. Or simply trust the defaults, which use the internal LipidOracle library and a permissive RT checking routine (LiRI).

WORKFLOW:
  lipidoracle: True       # internal MS1/MS2 annotation engine
  acyl_analysis: False    # No EAD/UVPD analysis of acyl chains
  rt_check: liri          # False | legacy | liri | hydra

What happens on a run

Each stage narrows the candidate set and raises the identification level of the matches it produces. A typical workflow concludes in less than 10 sec for CID data, and less than 5 min for EAD data.

Load spectra

Reads MS2 and MS1 from the MGF. An m/z target list and internal standards can be pinned in.

input

Build libraries

Internal LipidOracle library, optionally LipiDex, LipidBlast, and your own CSV libraries.

setup

Match on accurate mass

Identifies features by precursor m/z against every library in play.

idlevel 1

Match on MS2

Every idlevel 1 hit that carries MS2 goes on to fragment matching and scoring.

idlevel 2

Validate retention time

A class-specific model flags implausible hits. External RT anchors refine the fit.

filter

Resolve acyl chains

On EAD or UVPD spectra, locates C=C and oxidation positions by scoring simulated isomer spectra.

idlevel 3

Consolidate and export

Aggregates isomer candidates per spectrum, then writes results, diagnostics, and the dashboard.

idlevel 4

Traceable evidence

LipidOracle keeps track of what fragments were used to identify which molecular properties. The type of evidence is expressed in idlevel fields ranging from 1 to 4 with increasing granularity. Each level has its own confidence score.

For each compounds and idlevel, Lipidoracle enumerates and scores all isomers, and produces a consolidated output rooted in the information that was found.

The basis of the hierarchical annotation is provided by the built-in library.

IDLEVEL 1

Accurate mass

Matched on m/z alone. This happens when no MS2 is available. The detail doesn't go beyong lipid short names with total carbon and double bond numbers.

IDLEVEL 2

MS2 match

Ranked by score_L2, a hybrid of how well the weighted library spectrum was matched and how well the spectra correlate. It allows to confirm lipid class and possibly identify acyl chains and - rarely - regiosiomerism

IDLEVEL 3

Double-bond position in acyl chains

With EAD or UVPD spectra, it's possible to analyse the feature for C=C and oxidation position in its acyl chains. score_L3 compares simulated isomer spectra, with separate scoring for lipids and for oxidised PUFAs. The complexity increases with multiple chains.

IDLEVEL 4

Consolidation of isomers

One row per spectrum, aggregating all idlevel 3 candidates into a single expression that captures consensus across thousands of candidates.

Adaptive retention time checking

As many features might not have - good enough - MS2 spectra, MS1-based annotation remains an important part of the workflow but suffers from spurious false hits. LipidOracle implements two retention-time engines to check for RT consistency. They employ machine learning to learn within and across lipid classes, and flag implausible hits before they reach the output.

Both models are tuned automatically based on high-quality MS2 matches. An external RT library can be provided, but is not necessary if enough MS2 spectra are available for tuning.

See Retention-time checking for more details.

LiRI – the default

Builds a structural retention index per class, mapping carbons minus a fitted penalty for double bonds and oxygens onto observed RT. Conservative: a class with too few anchors gets no prediction at all rather than a rough guess. Safe but incomplete — classes without MS2 evidence in this run pass through unfiltered.

Evidence-based Per-class model

HYDRA – zero-shot coverage

Uses one shared calibration curve and predicts missing classes through chemistry features (headgroup composition, chain inventory, family indicators). Can flag an implausible hit in a class with zero MS2 confirmation in this run. Complete but requires tuning — stricter idlevel-1 settings can increase removals.

Chemistry-informed Cross-class features

Both RT checking engines are followed by a generic RT filter that removes wrong MS1-matches. It builds on the high-quality results produced by the RT engines, and it filters out in-source fragments.

Report ambiguous data faithfully

Multiple candidates often tie for the same score, or score within noise of each other. Rather than arbitrarily picking one, LipidOracle reports the ambiguity itself: CXSMILES depictions show every surviving candidate and the confidence score for each.

CXSMILES

Every candidate structure is encoded as CXSMILES, a canonical SMILES string that explicitly marks uncertain double-bond, oxidation, or connectivity positions. The extension with f:, m:, Sg:, ctu: blocks enable to precisely declare ambiguity in a machine-readable format. 

DG 18:1(9);OH(5)_18:1;OH
↓
C(CO)(O*)CO*.*C(=O)CCCC(O)CCCC=CCCCCCCCC.*C(=O)CC=CC.[OH]
|f:0.1,0.2,Sg:n:32:a:ht,Sg:n:35:b:ht,m:36:32.33.34.35,ctu:18,31| a+b=15
  • glycerol backbone
  • acyl chain undefined C=C position
  • movable C-OH
  • ambiguity in sn-regioisomerism

Structure depiction

The ambiguity is depicted in the structures shown in the dashboard, which are calculated on the fly. Alternatively, LipidOracle can expand variable parts to create one representative isomers for compatibility with RDKit

Outputs

Three files answer most questions. The rest of the run is written to diag/ so you can trace any call back to its evidence.

In addition, both the lipidoracle.yaml and the input *.mgf files are copied to the output folder for reference.
